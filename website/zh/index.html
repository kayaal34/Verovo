一个账单问题，和一个续约决定，需要不同的证据。

费用核验

对照适用约定与记录，检查某一笔具体收费。有支持材料的差异可以进入供应商复核；它还不是退款。

验收或续约

把可观察的工作与你写明的业务要求对照。即使每一笔收费都与约定一致，也可以单独委托交付核验。

缺证据就保持未知。更严格的业务要求，不会自动让一笔收费变成错误。本地核验只比较明确判据与你提供的观察记录。更完整的客户工作流仍待验证；不存在通用的自动化质量评分。

一张 $26,563.25 的 AI 发票，对到分。

一张合成账单、一个供应商、一个账期。核验从四段输入加输出重新计算用量，再逐行对账发票，直到只剩无法解释的残差。

按用量重算

$38,462.06——按合成用量导出，四段输入与输出的标价合计。

独立重算
发票总额

$26,563.25——扣除 $20,000.00 credits，加上 $6,000.00 席位费和 $1,956.96 税；后两项从不出现在用量数据里。

已知条目已解释
未解释残差

所有已知条目之后仍剩 $144.23。根因未知（状态 UNPROVABLE）；价格档位解读只是假设，需要合同价格表。不是退款主张。

未知保持可见

合成样本，不是客户账单：一个供应商、一个账期、USD、固定种子生成器（random.seed(42)）、Decimal 运算，只对合计做一次 ROUND_HALF_UP 到分（不是逐行；逐行四舍五入会让总额最多每行偏移半分，本示例未建模）。恒等式：38,462.06 + 6,000.00 − 20,000.00 + 1,956.96 + 144.23 = 26,563.25。成本导出比复算低 $7,254.73，因为它完全没有 cache-read 桶——每行缺失 $15–$150，是漏掉的条目，而不是按分取整造成的误差。对到分只证明在给定价格、规则和输入下算术一致。它不证明用量导出完整、价格公允或服务已交付；导出无法支持的部分保持 UNPROVABLE。复现：cd buyer-ledger/examples/ai-invoice-reconciliation && python3 make_demo.py && python3 reconcile.py（fixture 与脚本）。

只是随便看看？先看一份解释长什么样

合成 demo 显示 1 条重试链（含 3 次执行）和 7 次失败执行。这不能证明 7 个 bug 或 7 笔收费。下一步有用的检查是查看最长失败运行里的第一个错误。

读一份示例诊断。要检查你自己的会话，请在存有日志的那台电脑上运行 CLI。

安装帮助：macOS、Linux、Windows

使用 Python 3.9+。Windows 上如需要，用 py 代替 python。macOS/Linux 上没有 python 时用 python3。

如果 pip 提示 “externally managed” 或没有权限，使用本地虚拟环境：

不需要激活。后续命令使用同一个可执行文件路径。如果找不到 verovo，检查安装环境，不要用管理员权限全局重装。

下一步：检查你自己的日志，准备可分享的摘要
verovo check --json report.json
verovo share report.json --out summary.json
verovo validate summary.json

两个运行时都有日志时，自动发现优先选择 Codex。Claude Code 用 verovo check --runtime claude --json report.json。打开终端打印路径下的 HTML 报告；完整 JSON 与 HTML 留在本地。发送前先检查 summary.json。导出不是上传。

没有日志、报错或结果不符合预期？

最近七天没有日志？试试 verovo check --all，或用 --dir "/path/to/logs" --runtime codex 指向真实目录（Claude Code 用 claude）。空目录会产生输入错误，不是“一切正常”。命令失败时，先停下，不要继续跑导出命令。

Healthcheck 退出码 0 表示报告已运行，即使报告里有发现。退出码 2 表示输入/输出问题。UNPROVABLE 表示缺证据，不是失败，也不是干净结果。一致性检查中，退出码 1 表示某项不变量失败或必需但未证明。

报告可复现的工具 bug 时请附版本、命令、预期行为和脱敏后的错误。不要把原始日志、report.json 或凭据贴到公开 issue。报告可复现的工具 bug 是免费的。

01

尝试≠操作

尝试是执行事实。操作是逻辑意图。重试是同一个操作的多次尝试，不是“2 个操作，成功率 50%”。
